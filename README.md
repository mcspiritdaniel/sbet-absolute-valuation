# Handoff: SBET Absolute Valuation

## Overview

An interactive absolute-valuation model for SharpLink Gaming (NASDAQ: SBET), an
ETH treasury company. The app answers one question — what is a share worth on
assets and yield alone, before any claim about management's future capital
allocation — and lets an analyst move every input to see the answer change.

Two deliverables:

- `SBET Absolute Valuation.dc.html` — the interactive app. Three views
  (Overview, The Argument, Capital Structure), eight sliders, a live-price
  fetch, and a self-checking integrity strip.
- `SBET Absolute Valuation-print.dc.html` — a print/PDF edition of the same
  analysis, pinned to a fixed snapshot. No sliders, no fetch, no clock
  dependency.

Target: static deploy to Vercel. First live edition. Refreshed weekly.

## About the design files — read this first

**This is not a design reference to reimplement.** The two `.dc.html` files are
the finished artifact. They are reviewed, verified, and intended to deploy
as-is. Do not port them to React/Vue/Next, do not restyle them, do not
"productionize" the markup.

The work in this handoff is a small amount of scaffolding around them:

1. A build step that writes four data blocks into both files from a JSON
   snapshot (see **Weekly refresh**).
2. An `audit_app.py` that enforces cross-file invariants (see **Audit**).
3. Deploy hygiene: self-hosted fonts, `<title>`, favicon, OG tags.
4. One code change: an abort timeout on the price fetch.

That is the entire scope. If you find yourself rewriting the valuation logic or
the layout, stop — something has been misunderstood.

### Why the files look the way they do

Each file is a single self-contained document: a markup template, an inline
logic class holding the model, and inline styles throughout. There are no CSS
classes and no external stylesheet of our own by design — the pages paint
progressively from the first byte. Preserve that. Extracting styles into a
stylesheet or splitting the logic into modules will break the property it was
built for.

The files load a design-system bundle (`_ds/otherwhere-capital-design-system-.../`)
for a handful of components — `BridgeRow`, `SliderControl`, `GridCell`,
`NavBar`. Copy that folder to the deploy target and keep the relative paths
intact.

## Fidelity

**High-fidelity and final.** Colors, type, spacing, copy, and behavior are all
settled through many review rounds. Every number on screen is computed from
pinned constants — nothing is a placeholder.

## The model, in brief

Enough context to not break things. The full methodology is in the app's own
Methodology view, which is the authoritative statement.

- **Line in sand** = economic NAV per share + PV of the yield strip. The
  headline output. What you get if nothing new happens.
- **Economic NAV** = ETH + cash + other assets − liabilities − Black-Scholes
  value of warrants written against those assets.
- **Economic shares** = treasury-stock method: common + pre-funded warrants +
  in-the-money dilution net of exercise proceeds. This is the model's central
  methodological claim and the reason economic mNAV differs from the
  company-published figure.
- **Yield strip** = staking yield + protocol incentives − SG&A, capitalized
  over 10 years at 12%. The strip is **not uniform**: incentives decay 50% a
  year and are capitalized on their own schedule, separately from the flat
  leg. This split matters — a positive annual yield can produce a negative PV
  at low ETH prices, and that is correct.
- **Net optionality** = ATM option + ecosystem optionality − governance
  discount. Currently −1.00%, a small drag, so the justified price sits *below*
  the line.

### Two share-count bases, both legitimate

The company publishes ETH Concentration on **two different denominators**:
assumed diluted in its filings and press releases, basic-equivalent on its live
investor dashboard. The app carries both columns and names what each is
comparable to. Do not "simplify" this to one basis — the distinction is a
substantive finding, documented in Methodology C.

## Data flow and the single source of truth

Everything seeded comes from a weekly JSON snapshot generated by the model
workbook. The current one is `SBET_App_Snapshot_25Aug2026-a55ad6ef.json`
(included).

Each `.dc.html` file has exactly four contiguous static blocks holding data,
plus one print-only fifth:

| Block | Holds |
|---|---|
| `static ASOF` / `ASOF_SHORT` / `ASOF_LONG` | Valuation date, three formats. Every rendered date derives from these. |
| `static SNAP` | Market and balance-sheet seeds plus all model assumptions. |
| `static SRC` | Sourced facts that are not computed: holdings, release date, dashboard readings, close date. |
| `static TARGETS` | Independent expectations for the self-check strip. |
| `static OPTIONALITY_NOTE` (print only) | The frozen, build-time-computed equivalent of the main file's live `v.optionalityClause` — a net-optionality reading has no slider in print, so it must not be hand-typed prose either. See `build.py:derive_optionality_note`. |

Nothing else in either file contains a seeded number. Initial state, the reset
handler, the integrity strip's baseline, and the at-defaults test all derive
from `SNAP` through a `seedState()` method — so a value appears once per file,
not four times.

## Weekly refresh — the build step to write

This is the main task. Today it is a hand edit of four blocks in two files;
it should be generated.

Read the JSON snapshot and write `ASOF`, `SNAP`, `SRC`, and `TARGETS` into both
files. All four are contiguous `static X = {…};` blocks — a block-level
replacement, not a regex over call sites.

### TARGETS key mapping — do not infer this

`TARGETS` keys are named for the app's internal computed fields. Four of eight
match `checks{}` by name; four do not. A key-for-key copy silently drops half
the checks.

| TARGETS key | ← `checks{}` key |
|---|---|
| `lineInSand` | `lineInSand` |
| `mnavEconomic` | `mnavEconomic` |
| `navPerShareEconomic` | `navPerShareEconomic` |
| `ethConcBasic` | **`ethConcentration`** |
| `justifiedScenario` | **`mnavJustifiedScenario`** |
| `justifiedOnScenario` | **`priceJustifiedScenario`** |
| `priceJustifiedEconomic` | `priceJustifiedEconomic` |
| `yieldPV` | `yieldPV` |

Encode this mapping explicitly. Values are **strings**, and the number of
decimal places sets the comparison tolerance — emit the full precision the
workbook holds. Truncating silently loosens the check.

### Why TARGETS must be generated

These are hand-pinned literals that have to be re-pinned every week or they
fail against correct arithmetic. That failure has already shipped once: the
print copy carried pre-rebuild targets while its computed column was right, and
no check caught it. Generation removes the manual step entirely.

### A hard-won rule

`priceJustifiedEconomic` exists because the headline tile's figure was derived
correctly from checked inputs and still went a week unverified — long enough for
two people to independently confuse it with `priceJustifiedScenario`, which is
the same idea on a different share basis. **Pin anything a headline displays,
not just anything that feeds a calculation.**

### `optionStrike` is inferred, not sourced — follow-up for the workbook

`SNAP.optionStrike` (the employee option strike, currently $122.88) has no
field of its own in the model snapshot. The build step (`build.py`) derives
it algebraically from `fundamentals.fullExerciseProceeds` minus the warrant
and prefunded-warrant exercise proceeds, divided by the option count — the
same accounting `compute()` uses for `proceeds` in both `.dc.html` files.

This is inference standing in for a sourced input, which is exactly the
failure class `priceJustifiedEconomic` above is a rule about: a value can be
derived correctly from checked data and still be silently wrong if the
thing it's derived from ever changes shape (a new warrant tranche with
different accounting, a change to how the workbook reports proceeds). The
algebra would keep producing a number; nothing would catch it being the
wrong one.

Mitigated for now, not fixed: `build.py` recomputes `fullExerciseProceeds`
forward from the derived `optionStrike` and the warrant tranche table
through an independently-written formula, and fails the build if it doesn't
reproduce the snapshot's value to full precision. That catches a coding
regression in the derivation, but not a genuine change in the workbook's
underlying accounting — the round trip would still (correctly) fail loudly
in that case, but the fix is a judgement call, not automatic.

**Ask: have the workbook publish `optionStrike` directly in `checks{}`
(or `fundamentals`) next week.** Once it's a sourced field, this derivation
becomes a cross-check against it instead of the source, and can be
downgraded from "assert or fail" to "warn on mismatch."

## Audit — `audit_app.py`

Keep this **separate** from the workbook's regression harness. Those 18 checks
validate the model; a failing app check reporting as a model failure muddies
what a failure means. Run it wherever the app is built.

Assertions:

1. `SNAP` and `ASOF` are byte-identical across both files.
2. `SRC` is a **subset** relationship, not equality — the print copy omits
   `dashNavPS` because it has no sentence that uses it.
3. `TARGETS` matches the model snapshot's `checks{}`, key-for-key through the
   same explicit mapping `build.py` uses — imported from `build.py`, not
   re-derived, so the two can never silently diverge from each other.
4. No money-shaped (`$1,234.56`) or share-count-shaped (`217,031,714`)
   numeric literal appears outside `SNAP`, `SRC`, and `TARGETS` — scanned
   across the **whole file**, template included, not just the logic class.

   Bonus, not one of the four above but preserved for the same reason it was
   added: every `Component.X` reference resolves to a declared static. (From
   experience: the print copy once referenced `ASOF_LONG` before it was
   declared, rendering `undefined` into the header, and nothing caught it.)

Assertion 4 replaces an earlier version scoped to "3+ decimal places, logic
class only." That version shipped, and would not have caught the defect that
motivated this one: a hardcoded `$2,266.79` ETH price sat through two
snapshot refreshes and a deploy before it was noticed, in a `<p>` tag in the
template — wrong on both axes for the old rule (two decimals, not three;
template, not logic class). The wider version necessarily allow-lists more —
chart axis ticks, permanently-fixed historical capital-allocation narrative,
quarter-pinned GAAP figures, the "per 1,000 shares" unit convention itself —
each named in `audit_app.py`'s `ALLOWLIST` with a reason, the same discipline
as before: narrow the check, name the exceptions, never loosen the rule to
make the noise go away.

Assertion 4 is the one that would have caught most of what went wrong during
development. Every defect found in review was drift — a literal that stopped
matching its constant, or one file updated and not the other. None were
arithmetic.

## Deploy

Static build. Two HTML files plus the `_ds/` folder. Nothing server-side.

- **Self-host the fonts.** Currently Google Fonts CDN — Playfair Display, IBM
  Plex Sans, IBM Plex Mono. The design system flags this for production.
- **Add `<title>`, favicon, OG tags.** None exist. The link will get shared.
- **Add an abort timeout to the price fetch.** It has none, so a hanging
  request leaves the status strip amber indefinitely. `AbortController` with a
  few seconds is enough; the existing catch already falls back to the seed
  correctly.

### Deliberately not doing

**No CoinGecko proxy for this edition.** The endpoint is unkeyed, requests are
per-visitor-IP, and traffic won't approach a rate limit. A serverless proxy
would add a secret to manage and a cache-invalidation question to an artifact
whose numbers are re-pinned weekly from verified closes. Revisit if intraday
accuracy is ever wanted or the fetch starts failing visibly.

**The print copy stays hand-authored, not generated from the main file.** Its
differences from the app are deliberate and numerous — no sliders, no fetch, no
market-hours logic, condensed panels, a differently-argued section C, its own
section lettering, a smaller `SRC`. A transform spec covering all that would be
about as complex as the file it produced. The build step writing all four data
blocks into both files gets the same protection where it matters, and
`audit_app.py` backstops it.

**No shared constants module.** The statics are read at class-definition time to
seed initial state, so a late-resolving import would leave the page with no data
on first paint.

## Things that must not be "restored"

Removed on purpose during review. Each will look like an omission.

**In the print copy:**

- The CoinGecko fetch and its `pendingEth` / `pendingAt` plumbing. It is a
  fixed snapshot artifact; it must not make a network request or vary by when
  it is opened.
- All market-hours branching. `open`, `ethStamp`, and the status color are
  constants there.
- Interactive language. "Apply", "click", "drag", "reset" have no meaning on
  paper. One such string shipped before it was caught.

**In both files:**

- Direction words are computed from live sign, never hardcoded. "Above" /
  "below", "discount" / "premium", "drag" / "addition" / "wash" all flip. Three
  hardcoded "below"s were found in one test by pushing the price above the
  line; assume a fourth exists if you add copy.
- Magnitudes are absolute values with the direction word supplied separately.
  A signed percentage under a directional label reads as `-5.8% below`.
- The incentive decay rate in prose derives from `incentiveDecay`, not a typed
  "50%".
- The ETH slider's `min`/`max` are computed as seed ± a multiple of the step,
  so the seeded price is always reachable on the track. Absolute bounds of 750
  and 8000 meant the slider could never return to its own default, because a
  daily close is essentially never a multiple of 10.

## Number formatting conventions

Consistent across both files. Worth knowing before adding anything.

- Dollar figures: **2 decimals**. `$10.12`, `$2,442.01`. Comma separators.
- ETH concentration (per 1,000 shares): **4 decimals**, all three bases. The
  fourth decimal carries information in the buyback-gaming argument — round it
  and the table's point disappears.
- Multiples: 4 decimals in the integrity strip, 2 elsewhere.
- Pinned constants in `TARGETS`: full precision, as strings.
- American spelling throughout (`capitalized`, not `capitalised`).

## Testing

Four tests found real defects during review. Worth repeating after any change.

1. **Sweep all eight sliders to both extremes.** 16 states. Check for NaN,
   blank, and broken direction words.
2. **Push SBET above the line (~$11.21).** This is where discount/premium
   language inverts. It found three hardcoded direction words that no other
   test could reach.
3. **Drop ETH below the liquid-token carrying value (~$1,449).** The GAAP
   comparison paragraph flips sign, direction word, and framing clause
   together.
4. **ETH at $750.** Net annual yield stays positive while the strip's PV goes
   negative — only possible because the two legs are capitalized separately.
   Collapse the decay split and this test goes positive, visibly.

Also check: the integrity strip reads "matches what is on screen" at defaults
and "screen is showing edited inputs" the moment any input moves, and the reset
button restores every input including the three optionality sliders.

## Design tokens

From the bound design system. Do not invent values.

**Color** — deep navy at three lightnesses (headings/figures, body, labels); a
single gold accent `oklch(0.76 0.13 82)` for the 3px topbar stripe, slider
thumbs, and section labels; white page; `oklch(0.975 0.006 258)` for summary
rows. Green positive, red-orange negative. No gradients, no shadows, no blurs.

**Type** — three fonts, strict roles. Playfair Display for hero numbers and
section titles. IBM Plex Sans for all body copy. IBM Plex Mono for every
number, ticker, and ALL-CAPS label.

**Layout** — max-width 1600px, 40px gutters (20px mobile). Sections divided by
1px borders, not cards. Border radius effectively zero. Information organized
by rules, not floating panels.

**Motion** — 150ms color and border transitions on buttons only. Charts have
animation explicitly disabled. Static precision, not kinetic UI.
